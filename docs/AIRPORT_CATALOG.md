# Airport catalog fallback

`src/data/world-airports.json` is the airport file supplied for this project, stored as JSON for the application's bundler. It contains airport locations and attributes such as IATA code, municipality, country, airport type, and scheduled-service flag. It does not contain city-center coordinates or road distances. Its upstream publisher, refresh date, and redistribution license were not included with the file; confirm those before redistributing or deploying the catalog.

The server-only lookup in `src/server/airports/airport-catalog.ts` is a fallback when Duffel's airport/city name suggestions return no match. It only returns airports with a three-character IATA code, a large/medium/small airport type, and `scheduledService: yes`. The catalog is a candidate directory only; Duffel's place lookup and offer search remain authoritative for provider-supported airports and current flight inventory.

The fallback calculates great-circle distance from the matched airport coordinate to nearby airport coordinates. This is an airport-to-airport reference distance. It is **not** a city-center or driving distance because this dataset has no city-center coordinates. The UI states this limitation. Do not relabel the measurement as distance from the city until an authorized geocoding source supplies a verified destination coordinate.

The configured independent-flight provider also uses this local catalog for airport resolution. As of October 22, eligible records, normalized names and token sets are prepared once per server module. Exact IATA map points use an index; nearby candidate results use a maximum 256-entry cache keyed by query, country and result limit. Callers receive copies. This is static location caching, separate from expiring supplier fares; it does not establish flight availability. Middle East and South America city candidates have explicit catalog-checked gateways. See the [measured efficiency review](EFFICIENCY_BENCHMARK_2026-10-22.md).

Town lookup now also uses non-commercial airfields as geographic references. They are excluded from automatic flight endpoints. When the reference has no scheduled commercial service, nearby scheduled large/medium airports within 160 miles in the same country are preferred; small scheduled airports remain a fallback where no larger option exists. For example, Santa Monica Municipal (SMO) locates Santa Monica but the default flight endpoint is LAX, with Hollywood Burbank (BUR) available as an alternative. Banff still defaults to Calgary (YYC); Whistler resolves through Vancouver (YVR). These are flight gateways, not renamed trip destinations, and ground travel is excluded from fares.

The client resolves city names through the lookup instead of trusting previously inferred `resolvedCodes`, including for the return endpoint. Explicit acceptable airport codes still take priority. A default gateway does not mean every nearby airport's fares were compared. Unknown places without a catalog reference or a verified gateway are not guessed.

Validation: 437 automated tests passed (one benchmark test intentionally skipped), TypeScript and targeted ESLint passed, and the production Webpack build succeeded. Regressions cover Santa Monica/state-qualified names, LAX/BUR selection, excluding SMO from automatic choices, Banff and Whistler gateways, incorrect-country suggestions, provider fallback and an SFO → YYC → LAX itinerary. These checks exercised airport resolution without requesting paid fares or making bookings.

Running HTTP checks also returned 200 for Santa Monica and Santa Monica, CA (first candidate LAX), Banff (YYC), and Whistler (YVR). The rebuilt public site served sign-in with 200 and kept unauthenticated flight-place lookup protected with 401.
